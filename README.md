# 暗号

暗号是一个由真实内容停留与感受驱动的闭测社交产品。当前版本已经从静态原型升级为可持久化的全栈 MVP。

`main` 是最新版的唯一长期分支，已整合暗号实验 MVP、AI 开场白与 Orca / Harness。用户从每日 3 条精选内容或自己带来的外部链接中，留下一句真实表达，并与在同一处停下来的人完成一次有内容起点的对话。原版入口仍保留在 `/index.html`；早期版本以归档标签保存，后续功能使用短期分支，详见 [分支与版本管理](docs/BRANCHES.md)。

内测内容池目前包含 24 条真实可播放的短内容，覆盖生活节奏、关系态度、城市观察、运动、阅读、动物、科技、幽默和人生选择等主题。每条内容都配置了可用于验证回声链路的测试停留，但不会伪装成真实线上用户。

## Orca 持续迭代与大模型

- [Orca 使用指南](docs/ORCA.md)：项目启动、迭代命令、跨会话恢复与验证。
- [工程工作流拆分](docs/WORKFLOWS.md)：各条工作流的输入、输出、验收和下一步。
- `npm run dev:ai`：沿用当前进程模型配置，启动带 AI 开场白的本地服务；产品内同意后才调用模型。
- `npm run verify`：语法和离线回归；`npm run ai:doctor`：不暴露密钥的配置检查。
- `npm run ai:doctor -- --cloud`：检查云端 AI 配置；`npm run ai:smoke -- --all --cloud`：3 次合成真实请求验证开场白、建议回复和自动代回。云端需独立 HTTPS 模型服务，不能使用电脑上的代理，详见 [公网部署](docs/DEPLOYMENT.md)。

- `npm run harness -- new "本轮目标"`：记录任务，按计划、实现、验证推进；详见根目录 `AGENTS.md`。
- [Agent 与 Harness 管理](docs/AGENT-ADMIN.md)：`/agent-admin.html` 调整模型、提示词补充、额度、超时、并发与代回总开关，支持配置版本及恢复；首次启动后持久化后台版本优先于同名环境参数，凭证仍由环境注入。

## 自动代回与接管

实现边界与验证记录见 [自动代回说明](docs/AUTO-REPLY.md)。

在回声或好友聊天页点击“Agent 建议 / 自动代回”，阅读说明后选择“同意并开启自动代回”。服务端会回复当前未回复的真人消息，之后收到真人新消息继续处理；离开页面也会继续，服务重启会恢复尚未回复的消息。点击“我来聊”或直接发送消息停止当前会话代回，其他会话不受影响。双方都能看到“Agent 代回”标识；Agent 自动消息不触发另一方的自动回复。

开启服务端模型需使用 `npm run dev:ai`，或注入 `ANHAO_LLM_ENABLED=true` 与现有模型配置。自动代回仅发送通过校验与审核的模型结果；模型关闭、限额、超时或失败会停止并提示接管，不自动发送固定备用内容。建议草稿仍可使用备用内容并由用户确认发送。复用每日与并发配额，默认每用户每天 10 次、全局每天 100 次（与开场语共用账本）。

模型输入为当前内容标题、自己的感受（好友聊天使用本人简介及对方昵称）和最近 10 条双方聊天。当前实现面向单个服务进程及其持久化磁盘，多个副本的实时通知不共享；测试未验证多实例部署或模型实际回复质量。

## 聊天分享与表情包

回声和好友聊天输入框左侧的「＋」可分享 HTTP / HTTPS 链接、上传图片 / GIF，或选择六款内置贴纸。链接可填写标题；图片和贴纸先预览再确认发送，也可取消。发送失败保留选择供重试，文字草稿不受影响；点击已发送图片可放大。

图片支持 PNG、JPEG、GIF 和静态 WebP，每张不超过 3MB，最长边 4096 像素且总像素不超过 1600 万；动态表情使用 GIF。附件保存于持久化磁盘，只允许当前会话双方登录后读取，拉黑或删除好友后不能继续访问。链接只展示手填标题和域名，不抓取网页内容；图片内容尚未接入自动审核。

手动分享与文字发送一样，会停止当前会话的自动代回。模型仅收到图片 / 表情包占位及不可推测内容的提示，链接只提供标题，不发送图片文件或抓取链接正文。上传配额与备份要求见 [公网部署](docs/DEPLOYMENT.md)。

## 配置

复制 `.env.example` 中需要的配置到部署平台的环境变量。服务本身不自动读取 `.env` 文件，生产环境应由部署平台注入变量。

- `SMS_WEBHOOK_URL`：短信服务适配器地址，会收到 `{ phone, code }`
- `WECHAT_APP_ID`、`WECHAT_APP_SECRET`：微信认证服务号或公众号凭证
- `PUBLIC_URL`：公网 HTTPS 地址，用于微信回调
- `DATA_DIR`：持久化磁盘目录
- `ADMIN_KEY`：内测数据后台的管理密钥
- `BETA_TEST_CODE`：可选的 6 位统一闭测验证码；配置后生产环境不会发送短信，也不会把验证码返回给页面
- `MODERATION_WEBHOOK_URL`：可选的第三方内容审核适配器
- `DEMO_MATCHING_ENABLED`：仅用于本地演示；生产环境默认关闭，真实闭测不要开启

未配置短信服务时，非生产环境返回固定测试验证码；线上小规模闭测可以临时配置 `BETA_TEST_CODE`。统一验证码不验证手机号所有权，拿到测试码的人可以用任意未注册手机号创建账号，因此只适合受控内测，接入正式短信后应移除。未配置微信凭证时，界面会说明该能力尚未启用。

## 内测数据后台

打开 [http://127.0.0.1:4173/admin.html](http://127.0.0.1:4173/admin.html)。本地默认管理密钥是 `anhao-admin`，正式部署必须通过 `ADMIN_KEY` 换成长随机密钥。

后台展示注册、资料完成、留下感受、进入回声、共同回答和真实聊天漏斗，也可以处理用户举报。审核默认使用内置规则；配置 `MODERATION_WEBHOOK_URL` 后会优先调用外部审核服务，并在不可用时回退到内置规则。

## 部署提示

这个版本需要 Node 服务和持久化磁盘，不能再只使用 GitHub Pages。正式部署还需要 HTTPS、短信服务、微信回调域名、数据库备份、接口限流和隐私协议。当前设备通知依赖页面保持打开；App 关闭后的系统推送需要继续接入 APNs、FCM 或微信服务通知。

部署步骤与持久化要求见 [公网部署](docs/DEPLOYMENT.md)。Railway 将持久化磁盘挂载到 `/data`，并设置 `DATA_DIR=/data`、`NODE_ENV=production` 和 `ADMIN_KEY`。生产环境默认监听 `0.0.0.0`，端口由部署平台的 `PORT` 环境变量提供。必须配置 `SMS_WEBHOOK_URL`，或仅在受控内测时配置 `BETA_TEST_CODE`；服务只部署一个副本，实时连接不能跨实例共享。
