# Agent 代回与接管原型

直接用浏览器打开本目录 `index.html`，不需要登录、安装依赖或启动后端。页面沿用暗号聊天页的布局；产品服务器的静态资源白名单不开放本目录。

## 体验流程

1. 默认进入“模拟·默默”的对话，点击“让 Agent 替我回”。
2. 阅读模拟与拟议上下文说明，点击“同意并开启代回”，选择一种代回方式。
3. 对话中已有未回复消息时，稍后出现带“Agent 代回”标签的模拟回复。
4. 点击“演示：模拟对方发来消息”，体验继续代回。
5. 点击“我来聊”，或直接在输入框发送消息，立即接管当前对话；尚未完成的模拟回复会取消。
6. 返回列表并进入另一段对话。各段对话分别开启代回，列表显示状态；切换对话会保留各自的草稿，离开当前对话不停止已开启的模拟代回。

手动发送后约 1.2 秒会收到一条模拟对方消息，也可用演示按钮主动触发。回复是按所选方式提供的固定示例，连续消息在一次生成期间合并演示，不代表逐条回复或模型理解能力。

## 范围与待确认事项

全部人物、消息、回复和延迟均为合成演示。数据仅保存在页面内存中，刷新会重置；没有业务网络请求，不调用模型，不连接数据库，不发送真实消息。输入和列表预览均以纯文本显示。

页面提出的“标题、自己的感受、最近 6 条消息”只是待确认的模型上下文方案。真实代回的双方告知与同意、上下文权限、次数与费用限制、失败处理、持久化以及跨设备接管尚未实现。此原型不改变产品现有的 AI 开场语建议功能，也不代表已上线自动代聊。

## 验证

2026-10-21 在 Chrome 的 430px 与 375px 视口操作验证：首条及连续模拟代回、生成中手动发送接管、停止后重新开启时取消旧回复、准备过程中切换聊天、后台回复更新列表、不同聊天的草稿隔离、纯文本列表预览和返回路径。页面未出现脚本错误。仓库 `npm run verify` 检查内联脚本语法并运行离线回归。
