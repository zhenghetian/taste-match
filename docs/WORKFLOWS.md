# 暗号工程工作流

每次只选择一条流程下的一个目标，创建任务 ID。统一执行：需求与验收 → 范围内实现 → 独立审阅和离线检查 → 人工验收 → 记录下一步。入口和具体命令见 [ORCA.md](ORCA.md)。

| 工作流 | 输入 | 输出与验收 | 现有入口 |
| --- | --- | --- | --- |
| 产品与实验 | 一个用户问题、匿名反馈或闭测假设 | 一项可验证改动、事件定义、观察周期；不凭功能数判断效果 | `signal-mvp.html`、后台漏斗 |
| 内容与暗号 | 可使用的内容、内容 ID、本人表达 | 内容可播放、暗号保存和修改正确、重复提交不新增假记录 | `content-library.mjs`、signals API |
| 真人回声与聊天 | 两名真实参与者的同内容暗号 | 双方回答后解锁、授权隔离、消息持久化、拉黑生效 | echoes/messages API |
| AI 开场白 | 用户明确同意后，标题＋本人的感受＋共同问题 | 三条可编辑候选；不含对方回答、聊天、手机号；点击只填草稿 | `llm/icebreaker.mjs`、icebreakers API |
| 质量与 Harness | 本轮任务 ID 和改动 | 检查日志、通过/失败状态、源码指纹、剩余未验项 | `harness/`、`test/` |
| 发布准备 | 已验证的版本及目标运行环境 | 登录方式、持久卷、备份恢复、HTTPS、内容与隐私说明、回退步骤 | `railway.json`；正式发布单独执行 |

## 第一轮已经实现

- 工程任务状态 `pending → planned → implemented → verified → ready`，状态和证据保存在不提交的 `work/harness/`。
- `check` 实际运行离线测试，通过后保存源码指纹；代码改变后原检查不能直接用于推进 ready。
- Claude 的 `/anhao-iterate` 顺序调度理解、实现、验证；不依赖 Workflow 工具的 agent 用 npm 命令继续相同任务。
- AI 采用官方 Anthropic SDK；模型配置从环境读取，不复制 Orca 的凭据。`dev:ai` 可沿用当前网关的模型别名。
- 模型调用由代码控制为单次请求，无执行代码或自动发消息的工具。官方 API 默认开启服务端拒绝回退；兼容网关默认关闭该 beta 扩展，可显式配置。
- 每天全局/每用户调用数、并发数、输出 token 上限、请求时限、输入长度、结果格式和联系方式过滤都有代码约束。失败回退为固定问句。
- 调用预留及用量写入 `DATA_DIR/ai-harness.db`，重启不重置当天额度。日志只含版本、匿名用户摘要、耗时、状态和 token，不含提示正文或候选句。

调用次数和 token 上限不是精确金额预算。价格、缓存和网关扣费以供应商账单为准。这里没有无限重试或后台自动循环；SDK 重试关闭。当前仍按单实例部署，并发限制是进程内的。

## 接着迭代的任务

1. **上线登录**：统一测试验证码不能验证号码归属，真实闭测接短信或独立账号认证；补验证码发送频控。
2. **数据恢复**：备份主业务库及 AI 用量库，使用 SQLite 一致性备份，验证恢复。不要复制运行中的单个主 `.db` 当完整备份。
3. **AI 质量**：离线检查只覆盖约束和故障行为；下一轮用获得许可的样例人工检查自然度、相关性和冒犯风险，确定输入与预算后再做真实模型批量评测。
4. **闭测运营**：确认内容使用范围、隐私说明和举报处理人；让真人集中在少量共同内容中参与，观察有效对话与回访。

## 在 Orca 提出的任务示例

```text
/anhao-iterate 给暗号提交增加失败后保留草稿和重试，验收重复点击不会新增记录
/anhao-iterate 给短信验证码发送增加频控，测试不用真实短信
/anhao-review 当前任务ID
```

跨会话交接时粘贴任务 ID，让下一位 agent 先运行 `npm run harness -- context` 和 `show <id>`。保留已知未完成项，不把 verified 解释为线上验证或业务指标改善。
